# Skill Architect 制作过程

## 背景

用户发现一个大型综合思维类项目的主 `SKILL.md` 过大，像一本没有目录的书。每次对话都需要读取全部内容，导致 token 消耗高、维护难。

目标是改成：总目录 → 路由索引 → 按需读取技能包 → 需要验证时再查原书。

## 对话脉络

1. 用户提出主 SKILL 瘦身，并给出 DeepSeek 建议作为参考。
2. 讨论“技能索引模块”难点：目录和技能包必须对应，不能手工维护。
3. 先做现状审计：28 个能力簇、205 个技能包、索引缺少路径。
4. 实现自动生成路由索引：`build_skill_index.py` 扫描技能包并生成 `技能路由索引.md`。
5. 给 303 条 test-prompts 增加 `expected_clusters`，把路由准确率变成回归门槛。
6. 增加触发词、排除词、反馈日志，形成真实反馈闭环。
7. 完整备份主 SKILL。
8. 用户批准后删除主 SKILL 内嵌的 1202 行逐书判断尺。
9. 把 10 本早期基础理论书提升为活动技能包，覆盖核对 55/55。
10. 将整个流程封装成可复用 Skill，初名 `skill-slim`。
11. 增加通用 JSON 配置模式，支持任意 SKILL.md 指定章节外移。
12. 改名 `skill-architect`，建立独立发布项目。

## 关键决策

- 做架构外移，不做文字压缩。
- 主 SKILL 保留身份、核心判断尺、协议和路由入口。
- 外移内容进入独立技能包，按需读取。
- 先备份，再修改，失败可回滚。
- 索引必须自动生成，避免目录和技能包脱节。
- 验证必须包含路径、测试和路由准确率。
- 通用模式由用户通过 JSON 指定章节，而不是自动乱拆。

## 实际验证数据

- 主 SKILL：备份版 2034 行 → 当前 836 行，净减 1198 行。
- 删除：1202 行逐书判断尺。
- 活动技能包：215 个。
- 路由索引技能包路径：355 条。
- 原书路径：355 条。
- test-prompts：303 条。
- 预期簇全部命中：193/281。
- 零命中：0。
- 自测：`SELF_TEST_OK`。

## 长对话归纳能力（2026-08-20）

为 Skill Architect 增加“长对话 → 快照 + 精简技能包”的能力：

- 新增 `scripts/conversation_architect.py`，读取对话文件并生成 `conversation-snapshot.md`、技能包骨架和 `routing-index.md`。
- 新增对话快照模板、对话技能包模板和配置示例。
- 新增 `references/长对话归纳最佳实践.md`，明确该能力不压缩当前对话框，省 Token 主要发生在后续新对话。
- 增加简化续接：老对话说“帮我总结这个长对话”，新对话说“继续讨论 <问题>”，默认查找 `conversation-output/`。
- 根据资治通鉴项目 15:42 记录修正：收到“总结长对话”后必须先停止当前 SKILL 修改，并以整个对话框为范围生成 transcript，不能只总结主 SKILL 任务。
- 脚本层新增强制校验：默认要求 `conversation_scope: whole-dialog`，缺失或为主题片段时拒绝生成；只总结某主题必须显式 `--scope topic`。
- 新对话自动衔接：新增 `find_conversation_handoff.py`，跨目录搜索最新 `conversation-snapshot.md` 和 `routing-index.md`，避免用户手动给路径。
- 当前已开对话导入：新增 `import_conversation_handoff.py`，只读取最新快照、路由索引和匹配技能包，不复制旧对话完整历史。
- 跨用户转移：新增 `export_conversation_handoff.py` 和传输最佳实践，只传快照 zip，不传完整对话。
- 继续规则：快照保留“老对话最后一段回答”；新对话或当前对话继续时先展示，再停止让用户决定下一步，不自动执行旧任务。
- 脚本层强化：`find_conversation_handoff.py` 和 `import_conversation_handoff.py` 直接输出 `last_answer=...`，防止 Agent 继续旧任务。
- 修复 `rollback.py` 对备份目录回滚失败：现在会自动选择目录中最新非 `.sha256` 备份文件。
- 记录本机触发优先级：资治通鉴项目中 `simaguang-perspective` 优先，其他项目 `skill-architect` 优先；存在高优先级 Skill 时提醒用户显式调用，不做长时间项目分析。
- 新增低消耗快速导入模式：用户说“快速导入已总结长对话”时，只运行 `import_conversation_handoff.py`，展示最后一段回答后停止。
- 产品说明加入本机实际验证案例：30 轮快照、5 个主题技能包、Skill 包导出导入、触发优先级修复。
- 公开发布版和通用版均已加入，本机安装版同步更新。
