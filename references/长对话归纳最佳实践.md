# 长对话归纳最佳实践

## 什么时候使用

- 长对话已经积累了多个话题、决策或待办。
- 用户准备开启新对话，但希望保留核心上下文。
- 同一个 Agent 后续要处理同类问题，不想重新加载完整聊天记录。

## 工作流

1. 把长对话导出为 Markdown 或文本文件。
2. 在文件顶部声明 `conversation_scope: whole-dialog`，确保它是完整对话而不是当前任务摘要。
3. 运行 `scripts/conversation_architect.py --transcript <对话文件> --output-dir <输出目录> --skill-name <技能名>`。
4. Agent 根据 `conversation-snapshot.md` 中的归纳任务，填写核心结论、关键决策、待办和边界。
5. 用 `scripts/build_index.py` 或脚本生成的 `routing-index.md` 建立路由。
6. 用 `scripts/validate.py` 校验技能包路径。
7. 新对话只引用快照和对应的技能包，不复制整段聊天记录。

## 简化触发

### 老对话

```text
帮我总结这个长对话，生成 conversation-snapshot.md、技能包和 routing-index.md，完成后告诉我输出路径。
```

### 新对话

```text
继续讨论 <问题>。先读取 conversation-output/conversation-snapshot.md 和 conversation-output/routing-index.md，按需加载对应技能包。
```

默认输出目录为 `conversation-output/`。新对话中只要说“继续讨论 <问题>”，Skill Architect 会先运行 `scripts/find_conversation_handoff.py` 自动查找最新快照和路由索引；找不到时再查找当前目录 `conversation-output/`，仍找不到则请用户提供路径。

### 当前已开对话

```text
把总结过的长对话导入当前对话，继续讨论 <问题>
```

执行时运行 `scripts/import_conversation_handoff.py --topic <问题>`，只读取最新快照、路由索引和匹配技能包，不复制旧对话完整历史。导入当前对话仍会消耗快照和技能包的 Token，但远低于复制完整对话。

### 跨用户传输

发送方用 `scripts/export_conversation_handoff.py` 生成 zip，接收方用 `scripts/import_conversation_handoff.py --source <zip> --topic <问题>` 导入。只传快照和技能包，不传完整对话。详细方法见 `references/跨用户传输最佳实践.md`。

## 注意

- Skill Architect 不删除或压缩正在进行的对话上下文。
- 快照用于新对话，不是当前对话框内的即时省 Token。
- 生成技能包后，应保留快照作为原始决策依据。
- 最终归纳内容应由 Agent 或用户确认，脚本只负责自动提取候选结构。
- 用户说“总结长对话”时，必须覆盖整个当前对话框，不能只总结当前正在处理的 `SKILL.md` 任务。
- 收到总结请求后，先停止当前修改任务；不要先继续瘦身、改协议，再回头总结。
- 如果无法读取完整对话，必须请用户导出完整文件，不要手工生成一份只包含当前主题的 transcript。
- 只总结某个主题时，必须显式运行 `--scope topic`，且 transcript 顶部声明 `conversation_scope: topic`；默认 `whole-dialog` 不允许用主题片段冒充完整对话。
- 新对话或当前对话继续被迁移的问题时，先展示快照中的“老对话最后一段回答”，然后停止，由用户决定下一步；不自动执行老对话任务。
