# 瘦身最佳实践

## 核心原则

- 瘦身是“架构外移”，不是“删内容”。
- 主 SKILL 保留身份、核心判断尺、协议、路由入口。
- 大块低频内容外移到独立技能包，并通过路由索引按需读取。
- 每步都必须可验证、可回滚。

## 决策标准

适合外移：

- 超过 50 行、按书/模块/主题独立成块的内容。
- 只在特定问题中才需要读取的长判断尺。
- 有独立原书或技能包可支撑的内容。

应保留：

- 身份、认知上下文、核心判断尺、协议路由。
- 每次分析都需要的强制机制和输出纪律。
- 用户明确要求常驻的规则。

## 顺序

1. 审计：先看哪里占行数和字符。
2. 确认：让用户决定哪些外移、哪些保留。
3. 备份：必须先有完整备份和校验值。
4. 抽取：原样抽到外部文件，不顺手改写。
5. 路由：建立索引，保证按需能找回。
6. 验证：路径、测试、集成检查全部通过。
7. 回滚：失败时恢复到备份。

## 风险

- 外移后漏路由，等于“知识还在但找不到”。
- 只外移不验证，可能破坏触发词和调用协议。
- 没有备份就直接删，无法恢复。
- 验证只看文件存在，不等于行为没退化。

## 通用模式

- 用户通过 JSON 配置指定章节、输出文件和替换说明。
- `extract.py --config` 支持一次外移多个章节。
- 索引生成和验证都接受 `--root`，可以用于任意项目。
- 自定义测试通过 `validate.py --test-command` 接入。
- 通用模式仍必须先备份、后修改、再验证。
