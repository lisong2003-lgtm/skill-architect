# 触发优先级与故障排查

## 本机已知场景

- 本机某个高优先级 Skill 项目：另一个 Skill 可能接管“继续老版讨论”等表述。
- 其他项目或新对话：`skill-architect` 优先级高，应优先按快照续接。

## 对用户提醒

- 如果用户继续的是已总结长对话，但当前项目有另一个高优先级 Skill，应优先提醒用户显式调用：

```text
用 skill-architect 把总结过的长对话导入当前对话，继续讨论 <问题>
```

- 不要替用户抢优先级，也不要继续执行老对话里的项目分析、路由优化、蒸馏等任务。

## 快速续接

- 新对话中用户说“继续讨论 <问题>”时，先运行 `scripts/find_conversation_handoff.py`。
- 脚本会输出 `last_answer=...`。
- Agent 必须展示该内容后停止，由用户决定下一步。
- 如果长时间没有结果，应停止并提醒用户显式调用，而不是继续全量项目分析。

## 其他用户

- 其他环境也可能存在类似的高优先级 Skill 冲突。
- 当无法确认触发时，优先提醒用户显式调用 `skill-architect`，不要假设 Skill 能自动接管。
